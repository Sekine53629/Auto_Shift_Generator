このシステムでできること
希望休や確定シフトを手入力し、残りの空白セルを自動で埋めます。手で入力したセルは自動生成で上書きされません。生成結果は全てログに記録され、いつでも元に戻せます。

実際に何行目になったかは ShiftSetup_初期設定実行 の完了ダイアログと ShiftClick_セルフチェック で確認できます。

パレット用の3行は自動で用意されます（v2.8）。日付行の上には ★マーカー／本体／ラベル／年月 の4行が必要です。足りない場合、または3行がすでに何かで埋まっている場合は、ShiftSetup_パレット生成 が行を挿入して場所を作ります。日付行を含む以下の内容はそのまま下へずれるので、書いたものが消えることはありません。
すでにパレットがある場合は挿入しません（実行するたびに行が増えないよう、本体行の先頭が OFF かどうかで判定しています）。
医師名欄の決まり方　★マーカー行の直上5行を医師名欄とみなします。A列に 医師名 と入っている行があれば、そちらを上端として優先します（任意。入れなくても動きます）。行数を変えたい場合は ShiftCommon の DOC_BLOCK_ROWS を変更してください。

2-2. シートの初期設定（ShiftSetup）

シートを新しく作ったとき、または行構成を変えたときに実行します。通常の月次作業では実行不要です。

マクロ名やること
ShiftSetup_初期設定実行これ1本でOK。下の4つをまとめて実行し、結果をダイアログで報告します。あわせて全体設定が既定値と違う項目を一覧で出します（下記）
ShiftSetup_パレット生成日付行の直上3行にパレットを作る。3行が無ければ自動で挿入します
ShiftSetup_ヘッダ数式年月セルと祝日サマリーの数式をセット
ShiftSetup_集計行数式医師数(診) / 薬剤師出勤数 / 過不足 の数式をセット
ShiftSetup_集計列数式AH〜AM列の個人別集計をセット。公休(AH)と有休(AI)の振り分けは設定シート L11 に従って決まります
ShiftSetup_名前付き範囲更新「シフト入力範囲」「シフトパレット」「医師名リスト範囲」「備考行範囲」を貼り直し、廃止した旧名を消す
既定値と違う全体設定は、完了ダイアログの最後に出ます。 設定シートの全体設定（K/L列）は空欄のときしか書き込まれません。既に値が入っている欄は、マクロの版が上がって既定値が変わってもそのまま残ります。 これは施設が調整した値を勝手に戻さないための作りですが、裏を返すと「新しい既定値が届いていない」状態に気づけません。 そこで ShiftSetup_初期設定実行 は、既定値と違う項目を L11 ノルマ外の休み記号 / 現在=有休 / 既定=有休,夏休 のように一覧で表示します。

値は書き換えません。 意図して変えた設定ならそのままで構いません。身に覚えがない項目があれば、版が上がって既定値が変わった可能性があるので、手で直してください。
集計列の並びが変わりました（ShiftSetup v3.2）。 以前は 休 / ○早番 / ▲遅番 / ●遅半 / 5診出勤 の順でしたが、いまは 公休 / 有休 / ○早番 / ▲遅番 / ●遅半 / 5診出勤 です。 AH〜AL列の意味がすべて1つずつずれています。

集計列を参照している数式や別シート（検証用シートなど）がある場合は、ShiftSetup_初期設定実行 のあとに参照先を貼り直してください。マクロは集計列そのものは直しますが、他のシートからの参照までは追えません。

見出しは、マクロが過去に書いた文字（休 ノルマ休 など）であれば自動で新しい見出しに書き換わります。手で付けた見出しは残るので、その場合は中身とずれていないか確認してください。

薬剤師出勤数入力欄のうち 自動作成設定 の区分が 薬剤師 の行だけ、出勤記号（○◯▲●）を数えます

医師名スタンプの初期値はダミーです。 パレットの医師名（医師1〜医師10）は、ShiftSetup.bas の SS_PalVals を編集して実際の医師名に置き換えてください。個人情報のため、書き換えた内容はGitにコミットしないでください。

シフト表の出力（ShiftExport）

パレットの 出力 をダブルクリックすると、印刷用にシフト表を書き出します。ShiftExport_シフト表出力 を直接実行しても同じです。

項目内容

シート構造の調査（ShiftSurvey）

「思った位置に生成されない」「行を大きく作り替えた」ときは、まず ShiftSurvey_シート構造調査 を実行してください。読み取り専用で、シートを一切書き換えません。

シート調査結果 という新しいシートに、次の内容が書き出されます。

項目内容
1. ブック概要シート一覧と使用範囲
2. 名前付き範囲定義と参照先、解決できるかどうか
3. 現在の判定結果開始日セル・日付行・備考行・医師数行・入力欄・パレットをマクロがどう判定しているか
4. 行別ダンプ1行ずつ、A列の見出し・B列の種別・値／数式のある列数・最終列・行の高さ・書式
5. 列幅A列から40列分の幅と非表示状態
6. 自動作成設定メンバー表のヘッダーと全体設定（K／L列）の中身
氏名は伏せて出力されます。 既知の見出し以外のA列の文字列は (氏名1) のような表記に置き換わり、B列以降のセルの値は出力されません。そのまま共有できます。伏せたくない場合は ShiftSurvey の MASK_NAMES を False にしてください。

警告意味と対処
入力範囲が下すぎる範囲の下端が 医師数(診) の2行上を超えている。名前付き範囲「シフト入力範囲」の終端を直す
氏名の重複同名が2行ある。先に見つかった設定だけが適用されるため、区別できる氏名に変更
区分が対象外「薬剤師」「事務員」以外。出勤数に計上されないので修正
マスタ未登録シフト表にあるがマスタに無い。既定値（薬剤師・通常・遅番可）で処理されます
孤児マスタにあるがシフト表に無い。行削除や氏名変更の取り残し

STEP 0-2医師数の入力

4〜8行に出勤する医師名を記入すると 医師数(診) 行に自動集計されます。
必要出勤数 = 医師数 + 1（設定シート L10 で変更可）

STEP 1希望休・有休の入力

パレットで 希休 有休 夏休 を選び、該当セルをダブルクリック。

有休・夏休は公休ノルマの外です。 設定シート L11「ノルマ外の休み記号」に指定された記号（既定=有休,夏休）は公休ノルマに数えられず、公休が別途その分配置されます。つまり有休・夏休を取った分だけ月の休みが増えます。

既に運用中のブックは L11 を手で直してください。 設定シートは作り直されない仕組みなので、既定値を変えても既存のシートには反映されません。L11 が 有休 だけのままだと、夏休が公休ノルマを食います（夏休5日なら公休が11日→6日）。なお 有休※ は書かなくて構いません。判定は部分一致なので 有休 が 有休※ も拾います。

公休が足りているかは AH列「公休」で見てください。 この列は公休ノルマに数える休み（公休 + 希休）だけを数えるので、そのままノルマ（土日祝の日数）と突き合わせられます。ノルマ外の休みは隣の AI列「有休」に分けてあり、2つを足すと休みの総数になります。

1列にまとめた「休」（総数）は廃止しました。 夏休5日の人は公休6日でも総数は11になり、正常に見えてしまうためです。

STEP 2派遣・単発スタッフの入力

マスタで 勤務ルール = 手動 の人は自動配置されません。出勤日を手で入力してください。
入力した出勤は必要人数の計算に反映されるため、過不足行が正しくなります。

STEP 3確定シフトの先付け

「この日はこの人」が決まっている分を先に入力します。記号（○●▲）で入れれば出勤確定、公休 で入れれば休み確定として扱われます。

入れすぎに注意。 手入力を増やすほど自動配置の自由度が下がり、公休ノルマ未達や人員不足の日が増えます。必要な分だけ先付けしてください。

STEP 4シフト自動作成を実行

シフト自動作成 を実行します。内部の処理順序は次の通りです。

順処理内容
1整合性チェック入力範囲の位置と氏名の不整合を確認。問題があれば確認ダイアログ（中止できます）
2空行・集計行スキップ氏名が空の行に加え、医師数 薬剤師出勤数 事務員出勤数 過不足 合計 シフトパレット で始まる行も氏名として扱いません（v7.1.0）
3既存入力の保護入力済みセルを「出勤確定」「休み確定」に分類
4勤務ルール適用固定曜日・週N日・手動・通常に応じて仮配置
5週N日の絞り込み週あたり勤務日数を上限まで削る
6公休ノルマ配置土日祝と同数を誤差0で厳守。週2休基本＋余剰は2〜3連休に
7連勤上限の緩和上限超えを検出し、中央を休みにして他の公休と入替
8医師5名日の均等化忙しい日の出勤回数を個人間で誤差1以内に
9記号割当○（1名/日）→ ▲（最低3名）→ 残りを ● ▲ で均等
10記号の個人差均等化○●▲の月合計を誤差2以内に（同日で交換）
11書き込み＋ログ記録変更セルを全記録（復元用）
優先順位の設計
公休ノルマ（誤差0・絶対）　＞　連勤上限　＞　必要出勤数（努力目標）

必要人数を満たせない日が出ても公休は削りません。不足日は結果レポートと過不足行に表示されるので、派遣の追加投入などで調整してください。

STEP 5結果レポートの確認

実行後のダイアログに表示される内容です。

表示意味
入力範囲今回処理した入力欄のアドレス。意図した範囲か確認できます
対象者／スキップ行氏名のある行数と、空行・集計行として除外した行数
各人の集計出勤／休／連勤max／連休max／医5日／○●▲の回数
休業者の行マスタで 休業 に○が付いている人の行が灰色になります（解除すると自動で戻ります）
公休ノルマ未達空きセルが足りず配置しきれなかった。手入力を減らすか休日数を見直す
事務員が不在の日事務員ゼロの日数。回避を試みますが不可能な場合に発生
遅番が目標に届かない日▲の人数が設定値（既定3名）未満の日数
必要数に届かない日出勤数 < 医師数+1 の日数と最大不足人数

STEP 6過不足行で日別チェック

過不足 行がマイナスの日を確認します。対処は次のいずれか。

  • 派遣・単発スタッフをその日に追加投入（STEP 2 に戻る）
  • 誰かの公休を別日に移動（手修正）
  • その日は不足を許容する

STEP 7手修正で仕上げ

パレットでダブルクリック修正します。手動変更もログに記録されるため、後から戻せます。

5. やり直し・元に戻す

マクロ名動作
シフト変更を戻す直前のセッションを取り消して復元。繰り返し実行で1回ずつ遡れます（値・文字色・太字・背景色すべて復元）
シフト白紙化入力欄を全消去。これもログに記録され復元可能
シフトログリセットログを全消去。実行後は過去に戻せなくなります（期替わり用）。対象月を変更すると自動で確認ダイアログが出ます（年月セルは数式なので、その元になる AG 列の月数を書き換えたときに反応します）。ブックを開いてから最初の1回は出ません（開いた時点の月を記憶するだけ。次に月が変わったときから確認します）
対象月をスピンボタンで変える場合は、ボタンにマクロを登録してください。スピンボタン（フォームコントロール）がリンクセルに書き込む操作は、Excel の変更イベントを発生させません。そのため期替わりの確認が出ないことがあります。

スピンボタンを右クリック → マクロの登録で シフト期替わり確認 を選んでください。手入力で年月を変えた場合は登録が無くても確認が出ます。
「セッション」とは1回の操作単位です。自動作成1回・白紙化1回・手動での同時複数セル変更が、それぞれ1セッションになります。

6. メンバーの追加・変更

新しいスタッフを追加する

  1. シフトシートで追加したい位置に行を挿入し、A列に氏名を記入
  2. 自動作成設定 シートに1行追記（氏名・区分・勤務ルール・遅番可否）
  3. シフト設定チェック で警告ゼロを確認
マスタの行順はシフト表と揃える必要はありません。氏名で照合しているため、シフト表の行位置は自由です。

薬剤師と事務員を見やすく分ける

間に空行を入れて構いません。氏名が空の行は自動生成で完全にスキップされます（v7.0.0以降）。区切り線や背景色を付けた行も問題ありません。

また 医師数 薬剤師出勤数 事務員出勤数 過不足 合計 シフトパレット で始まる行は、入力範囲に紛れ込んでも氏名として扱われません（v7.1.0）。範囲がずれた時の保険です。

休業・退職する場合

マスタの「休業(○=休業中)」列に ○ を入れてください。その月は一切配置されません。シフト表の行は残しておいて構いません。

マスタA列に数式を入れないでください。 氏名を数式で自動取得すると、空行を入れた時に空の値が混入し、区分・休業などの手入力列との対応がずれます。氏名は直接入力してください。

8. 困ったときは

症状原因と対処
誰もいない行にシフトが入るv7.0.0で修正済み。モジュールが古い可能性があります
原因がわからないC:\VBAErrorLogs\ の当日CSVを確認。モジュール名・処理名・行番号・変数の値まで記録されています
休業設定が効いていない氏名がシフト表と一致していない。シフト設定チェック で確認
特定の人だけ設定が反映されない氏名の綴り違い（全角/半角・スペース）。または同名が2行ある
ダブルクリックが反応しないパレットが OFF モード。切替 か記号を選ぶ
パレットの位置がずれたShiftSetup_パレット生成 で作り直す（日付行の直上3行に配置されます。3行が無ければ挿入されます）
「入力範囲が医師数(診)の2行上を超えています」行を増やして緩衝行が埋まっている。ShiftSetup_名前付き範囲更新 を実行すれば直ります
入力できる行が足りない範囲の下端が上すぎる。同じく ShiftSetup_名前付き範囲更新 で直る
集計行にシフトが入るv7.1.0で除外済み。モジュールが古い可能性があります
範囲がおかしいShiftClick_セルフチェック で範囲と参照元、下端の妥当性を確認

人員不足の日が多い公休ノルマ優先の設計上の結果。派遣投入か L10 の見直し
